**Goal:** Judge-facing technical documentation that backs the architecture,
cloud, and AI claims with repository evidence: how the two gates and the
seven-field comparison work, who owns each decision, how the cloud
deployment is built and secured, how the AI is constrained, and how a
stranger runs, resets, and repeats the demo. The root `README.md` is out of
scope for this issue.

**Architecture:** Four focused documents under `docs/` plus one reference
page, each linking to the code and tests that prove its claims:
`docs/architecture.md`, `docs/ai.md`, `docs/cloud.md`,
`docs/demo-runbook.md`, and `docs/references/third-party-notices.md`.

**Tech Stack:** Markdown in the repository style guide
(`docs/references/markdown-style.md`).

**Spec:** GitHub issue #44 (excluding the root README); `docs/TRD.md`;
`docs/references/deployment.md`; research
`docs/research/build/cloud-and-ai-claims.md`.

## Global Constraints

- Style: one H1 per file, short intro, `Contents:` list, ATX headings,
  80-character wrapping except links/tables/code, reference links for long
  URLs, explicit repo-root paths for internal links.
- Every claim about behaviour links to the file that implements it and, where
  one exists, the test that proves it.
- Decision ownership wording, verbatim in meaning: Gemini 3.5 Flash extracts
  only scanned or locally ambiguous documents; pinned `jev-1.13.0` makes the
  typed decisions (email category, document role, textual equivalence);
  deterministic Python owns preflight, parsing, normalisation, numbers,
  schema, state, and persistence; a named human owns consequential
  dispositions.
- Latency or score figures appear only from retained artifacts (the
  benchmark JSON under `apps/api/scripts/benchmark-results/`); never cite the
  historical Flash-Lite study as Flash evidence.
- Say plainly what is prepared (the seed decisions file) versus live (judge
  uploads), and that the preliminary deployment is synthetic-data-only.
- Cloud Run region does not prove model inference residency.
- Commands shown must be verified against a clean checkout (record the
  verification in the PR).

### Task 1: Architecture overview

`docs/architecture.md`: the product in one paragraph; Gate 1 (every received
email accounted for and categorised), Gate 2 (the independent expected-
shipment ledger reconciled to cases, including `SYN-042` as `MISSING_CASE`),
and evidence comparison (valid SI/draft-BL pairs over seven fields with the SI
as reference); the decision ownership table; the processing flow and
structural-reason precedence (short, linking `docs/TRD.md`); a module map
of `apps/api/app/*` and `apps/web/src/*`; the data model (tables and their
append-only guarantees); guest sessions, the seed baseline, and Reset All;
the public `/judge` flow and its failure contract; the API reference link
`docs/references/api.md`.

### Task 2: AI documentation

`docs/ai.md`: models and pinned versions; the extraction route (when Gemini
is called, the structured schema, grounding, approximate scan anchors, the
cache key); the Jev questions (category `Choice`, document-role `Choice`
without file names, equivalence `Noul` after normalisation) and the locked
bands with batch versus interactive mapping; what is never asked of a model
(numbers, file safety, state); the fail-closed provider policy (second
Gemini key only on 429, audited; no other provider; visible retry states);
prompt and schema version registry; measured latency (from the artifact, or
"not yet measured" with the reason); limitations and production gates.

### Task 3: Cloud documentation

`docs/cloud.md`: the single Cloud Run service serving FastAPI and the React
build; the migration job; PostgreSQL as the system of record; private GCS
objects with uniform bucket-level access and public access prevention;
Workload Identity Federation and the exact Secret Manager mapping;
Artifact Registry; observability; cost guardrails; the synthetic-only data
policy and residency caveat. Link `docs/references/deployment.md` for
operator detail instead of repeating it.

### Task 4: Demo runbook

`docs/demo-runbook.md`: prerequisites; local setup (`uv sync`,
`uv run uvicorn app.main:app --reload --port 8080` in `apps/api`;
`bun install`, `bun run dev` in `apps/web`; the root Dockerfile) with the
required environment variables and no secret values; the seed baseline
(what it holds, where it comes from, how prepared decisions are labelled,
how to regenerate it); guest-only entry (the email and password fields are
presentational); direct `/judge` access and what a judge should try; Reset
All and a repeatable five-minute demo script a new teammate can follow
without insider steps.

### Task 5: Third-party notices

`docs/references/third-party-notices.md`: runtime dependencies with their
licences (PyMuPDF under AGPL-3.0 with the network-use note and the
commercial-licence alternative, openpyxl, python-docx, google-genai,
typesafe-sdk, FastAPI, SQLAlchemy, React, Cytoscape.js, fonts, icons), the
synthetic dataset's provenance, and how the MIT-licensed repository keeps
third-party terms intact.
